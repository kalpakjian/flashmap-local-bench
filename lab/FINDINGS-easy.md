# 白話版：FlashMap 到底有沒有壞？

> 給不想讀數字的人。嚴謹版（含全部量測表）在 [`FINDINGS.md`](FINDINGS.md)。

---

## 一句話

**FlashMap 沒有壞，是「尺」不夠精細。**
我們拿一把刻度很粗的尺去量兩個幾乎一樣長的東西，量出來「一樣長」，
然後怪其中一個東西長錯了。

---

## 打個比方：兩台只能顯示兩位小數的計算機

假設有兩筆金額：**10.004 元** 和 **10.006 元**。

- 用「只顯示到小數第二位」的計算機（＝ bf16）：兩筆都顯示 **10.00**
  → 看起來一模一樣，無法判斷誰大。
- 用「顯示到小數第六位」的計算機（＝ fp32）：**10.004 < 10.006**，一目了然。

模型輸出下一個字，就是這樣「比大小」比出來的。當兩個候選字的分数**幾乎一樣**時，
bf16 會把它們壓成同一個數字，於是「選哪一個」就變成**丟銅板** ——
而且丟的結果還取決於程式內部的實作細節（誰先被掃到）。

實測就是這樣：分歧點的兩個候選字，分數差常常是 **0**（真的完全一樣），
或是 0.125、0.25 這種「刻度格點上的數」。真正的差距其實只有 0.06～0.32，
遠小於尺的刻度。

---

## 為什麼「只差一個字」，最後差了几十個字？

因為這是**接龍**。開頭第二個字一旦選了「solve」而不是「break」，
整段文章的走向就完全不同了 —— 所以最後長度會變成 217 字 vs 155 字。
看起來很誇張，其實**只翻了第一個字**。

---

## 為什麼「一次檢查 16 個字」和「一次寫 1 個字」答案會不同？

FlashMap 的運作像這樣：

> 小助手先猜接下來 16 個字
> → 老闆（真正的模型）**一次把 16 個字全部核對**
> → 對的就留、錯的就改成老闆自己選的字

所以**最終每一個字都是老闆選的**。這一點我用程式逐一驗證過：
9/9 題、單題最多 479 個字，全部等於老闆自己的選擇。

問題在於：老闆「一次核對 16 個字」和「一次只寫 1 個字」時，用的是
**兩種不同的計算姿勢**。數學上完全等價，但在 bf16 下，兩種姿勢算出來的分數
會在最後幾位有極微小的差異。剛好在「丟銅板」的位置上，這點差異就足以讓它選另一個字。

我用 fp32 重測同一個位置：三種姿勢的差異只有 0.00001～0.00006，**完全不會翻盤**。
所以「姿勢會影響答案」這件事，**只在 bf16 才會發生**。

---

## 那 HF 算出 217 字、vLLM 算出 155 字，是誰錯了？

**都不是。** 那個位置是真的 50 比 50 的平手（差距精確等於 0）。
vLLM 和 FlashMap 剛好都往同一邊倒，HF 的 `generate()` 往另一邊倒 ——
就像兩個人丟同一個銅板，一個拿到正面一個拿到反面。
**在 bf16 下，「標準答案」本身就不唯一。**

我也順手排除了其他可能：不是 prompt 不一樣、不是 chat template 不一樣、
也不是基準的呼叫方式不一樣（四種寫法在 bf16 下輸出**一字不差**）。

---

## 真正壞掉的是「量測工具」，不是 FlashMap

| 問題 | 白話說明 |
|---|---|
| 量錯單位 | 原本的腳本去查伺服器指標，結果把「時間戳」（17 億這種數字）跟真正的計數器**加在一起**了，所以算出「接受率 17.0」這種不可能的數字。修好之後是 **24.71%**。 |
| 比錯東西 | 原本比的是「解碼後的字串」，這會把結尾符號、空白差異吃掉。改成比 **token id**（跟原作者一樣的作法）。 |
| 安裝腳本 | 傳了一個不存在的參數，所以會直接失敗。 |

---

## 你真正該記住的三件事

1. **加速是真的**：整體 **4.27 倍**（數學題 7.03 倍、程式 4.72 倍、聊天 2.37 倍）。
2. **FlashMap 是無損的**：它輸出的每個字，都是模型自己會選的字。
3. **要驗無損，請用 fp32**：同一個模型、同一組題目，fp32 下 **12/12 完全一致**；
   bf16 下只有 3/12。差別純粹是「尺的刻度」。

```bash
# 想自己驗一次（不需要 GPU server）
python acceptance.py --dtype float32                       # 8B 會 OOM，用 4B 對照組：
TARGET_MODEL=Qwen/Qwen3-4B DRAFT_MODEL=j-shen/FlashMap-Qwen3-4B \
  python acceptance.py --dtype float32                     # 預期 12/12
```
